# 领域文档

工程技能在探索本仓库代码时，如何消费领域文档。

## 探索前先读这些

- 仓库根目录的 **`CONTEXT.md`**（术语表）；
- **`dev-docs/adr/`**：阅读与你即将工作的区域相关的 ADR。

如果这些文件不存在，**静默继续**。不要提示它们缺失，也不要预先建议创建。`/domain-modeling`（经由 `/grill-with-docs` 与 `/improve-codebase-architecture` 调用）会在术语或决策真正落定时懒创建它们。

## 文件结构

本仓库采用单一上下文（single-context）布局：

```
/
├── CONTEXT.md           ← 术语表（固定在仓库根目录）
├── docs/                ← 只放使用文档（部署、配置、使用说明）
├── dev-docs/
│   ├── PRD.md           ← 需求文档
│   ├── adr/             ← 决策记录（NNNN-<slug>.md，编号从 0001 递增）
│   └── agents/          ← agent 协作约定（本文件所在处）
└── ...
```

约束：开发过程文档一律在 `dev-docs/`，不得放入 `docs/`。

## 使用术语表的词汇

当你的产出（工单标题、重构提案、假设、测试名）命名领域概念时，使用 `CONTEXT.md` 中定义的术语，不要漂移到术语表明确回避的同义词。

如果你需要的概念还不在术语表里，这是一个信号：要么你在发明项目不用的语言（请重新考虑），要么存在真实缺口（记下来交给 `/domain-modeling`）。

## 标记 ADR 冲突

如果你的产出与既有 ADR 矛盾，显式指出而不是静默覆盖：

> _与 ADR-0007（某决策）矛盾，但值得重开讨论，因为……_
